## 0 先用十五分钟理解问题

假设本轮只检索到记忆 12，内容是“面试安排在周四”。模型却返回：

```json
{"answer":"面试在周五","used_memory_ids":[999],"abstain":false}
```

`RecallAnswer` 允许 answer 是字符串、引用是整数列表、abstain 是布尔值，所以这个对象在结构上合法。代码去掉不存在的引用 999 后，得到空列表，但当前实现仍保留原答案和 abstain=false。

本课契约：接口提供的是有记忆依据的回答；模型未能提供有效引用时，应返回明确的弃答状态和安全说明，不把原来的无证据结论继续展示出来。有有效 ID 只是最低条件，不证明这段记忆支持答案中的每一句话。

阅读 [Pydantic AI Output](https://pydantic.dev/docs/ai/core-concepts/output/) 的基础部分，以及 [测试文档](https://pydantic.dev/docs/ai/guides/testing/) 的 FunctionModel 小节。不需要从头看完所有 API。

## 2 写下五条验收规则 十分钟

| 场景 | 模型或检索结果 | 本课预期 |
|---|---|---|
| 完全没检索到记忆 | memories 为空 | 不调用回答模型；abstain=true，引用为空 |
| 全部引用无效 | 模型给 [999]，本轮仅有 [12] | 弃答；清空引用；原来的确定性答案不可泄漏 |
| 模型不给引用 | used_memory_ids=[] 且 abstain=false | 同上，不允许作为正常回答 |
| 有合法也有非法引用 | [12,999]，答案确实只依赖 12 | 过滤 999；保留合法引用与这条正常回答 |
| 模型自己判断信息不足 | abstain=true，但错误附带引用 | 保持弃答，引用清空；返回合理的不足说明 |

这不是完整语义核验。特别是混合引用不能保证所有结论都可信；本课测试必须让答案只依赖合法记忆。后续独立评测再检查“引用存在但引用不支持结论”。
